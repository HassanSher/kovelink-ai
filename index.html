01 · THE PROBLEM

The owner is the whole office.

A three-car limo company or a one-truck carrier still has to answer the phone, quote the trip, assign a driver, invoice, chase payment, pay drivers and keep every permit and driver file current. Most owners juggle a dispatch app, QuickBooks, spreadsheets and a binder. Many pay a compliance service $150 to $400 a month just to remember the deadlines.

I started building with NPT Worldwide Limousine Inc., a black car company in Princeton Junction, New Jersey. They didn't need more software. They needed fewer places where the same ride lived.

02 · WHAT IT DOES

Start the company, keep it compliant, run it.

START

A free launch plan

A few questions turn into every federal, state and local step for the business, with the official site next to a plain-language guide.

STAY COMPLIANT

Deadlines that act

The launch plan becomes a renewal calendar. Driver and vehicle documents carry expiry dates, and an expired medical card can block the next assignment.

RUN

One record per ride

Booking, dispatch, a driver app, invoices and card payments, driver statements, the books and fleet maintenance all share the same ride.

03 · THE AGENT

How the agent handles a request.

Kovelink · ride #1042sample
  1. "Book Alex Morgan from JFK to the Langham at 4:15, SUV, and send the quote."
  2. Reservations · creates ride #1042, 3 passengers, SUV
  3. Billing · prices the trip from the rate card, drafts the quote
  4. Compliance · checks that Jordan Lee's license and medical card are current
  5. Dispatch · assigns Jordan Lee
  6. Asks first · "Send the $186 quote to Alex by text?"
  • Tools are scoped on the serverThe agent only gets the tools that the company's modules and the user's role allow. Every request is checked on the server, not only in the UI.
  • Escalates instead of guessingA confidence gate sends unclear or risky requests to a person. Sending money or messages always asks first.
  • Evaluations in CIAgent evaluations run in CI on every change. I fine-tuned and benchmarked routing models on a set of labeled requests. The best scored 89.7% on strict accuracy and 97.1% when it was allowed to hand off to a person.
  • Compliance answers cite sourcesAnswers point to the official state or federal page they came from, so an owner can check them.
FOR DRIVERS

Drivers see their status and their rides, start and finish trips, upload documents and read their statements. I simplified it in November based on the operator's feedback: one home screen, rides split into upcoming and past, and a sign-up link for each company.

To test on iPhone, I built a simulator harness that loads the app the way Chrome and the Google app do on iOS. It reproduced a crash drivers were hitting, and the fix cut memory use from 700 MB to 210 MB.

04 · HOW IT'S BUILT

One modular, multi-tenant codebase.

Features are modules. One registry declares what every module can do, and the server, the UI and the agent's toolset all read from it, so a taxi setup and a trucking setup run the same code with different capabilities.

FRONTENDReact, TypeScript, Vite; Capacitor for the iOS driver app
BACKENDNestJS, TypeORM, PostgreSQL, a background worker for reminders and jobs
AGENTTool calling over the module registry, per-role tool scoping, an escalation gate, evaluations in CI, fine-tuned routing models
INTEGRATIONSStripe and Square payments, Gmail, RingCentral phone and SMS, Google Maps, flight tracking
SECURITYRole-based access, MFA, bcrypt, session revocation, audit logs, OAuth 2.0, AES-256-GCM encrypted tokens, verified webhooks
DELIVERYRender; GitHub Actions on self-hosted runners I set up with Bash scripts, which brought CI cost to zero
05 · HOW I WORK

Written with Claude Code.

Most of Kovelink was written with Claude Code and other coding agents. I talk to the operator, decide what to build, write the spec, split the work so agents don't edit the same files, review the diffs and test the result.

Every change answers the same checklist: which module owns it, what the server enforces, what the agent is allowed to do with it, and how the database migration rolls back.

What worked

  • Building next to a real operator. Their feedback reshaped the driver app and the ride record.
  • Treating the ride as the single record. Features got simpler once everything hung off it.
  • Writing evaluations before trusting the agent with money or messages.

What I'd do differently

  • Narrow sooner. I built for too many industries before committing to transportation.
  • Budget CI early. Many parallel agents opening PRs ran through my GitHub Actions minutes fast.
  • Build the module registry first. I added it later and had to move existing features onto it.
